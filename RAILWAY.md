# Размещение на Railway

1. В Railway нажмите **New Project → Deploy from GitHub repo** и выберите `yaroslavlikh/monopoly`. Если приватного репозитория нет в списке, разрешите приложению Railway доступ именно к нему в настройках GitHub.
2. Railway соберёт приложение по `Dockerfile`. Настройки healthcheck и перезапуска находятся в `railway.json`. Отдельные Build/Start commands не нужны; приложение использует выданный Railway `PORT`.
3. Добавьте к сервису **Volume** с mount path `/app/data`. Приложение хранит в нём партии, входы и переписку.
4. В **Variables** задайте:
   - `DATA_DIR=/app/data`
   - `RAILWAY_RUN_UID=0` — для записи в том, который Railway монтирует от root. Локальный Dockerfile запускает приложение от `node`; этот параметр нужен именно при использовании тома Railway.
5. Оставьте **одну реплику** сервиса: текущее хранилище комнат — один JSON-файл и состояние одного процесса.
6. Сначала в **Settings → Networking** создайте Railway domain и проверьте создание комнаты и подключение второго игрока.
7. Добавьте **Custom Domain** `monopoly.todayway.ru`. В Cloudflare создайте DNS-запись с именем `monopoly` и типом/значением, которые выдаст Railway. Используйте также выданную запись проверки, если Railway её запросит. Корневой `todayway.ru` оставьте без изменений. Дождитесь подтверждения домена и выпуска HTTPS-сертификата.

Исходники не содержат текущую локальную партию, переписку и секреты входа. На Railway начнётся отдельная база комнат. Сохранённую локальную партию нельзя переносить через GitHub; при необходимости её переносят отдельно в защищённый том остановленного сервиса.

При перезапуске или деплое WebSocket-соединения переподключаются. Комнаты восстанавливаются с тома. Резервное копирование тома настраивается в Railway отдельно.

Документация: https://docs.railway.com/builds/dockerfiles · https://docs.railway.com/volumes · https://docs.railway.com/networking/domains/working-with-domains
